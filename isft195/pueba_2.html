¿Qué es un Bug Report?

Documento Técnico

No es un mensaje de WhatsApp. Es el documento oficial que comunica a los desarrolladores exactamente qué falló, dónde y cómo replicarlo.

Evidencia (Audit Trail)

Protege al equipo de QA. Si el error pasa a producción, el reporte de bug demuestra que el área de testing lo había detectado a tiempo.

Anatomía de un Bug Report

  • ID Único: Ej. PREC-045
  • Título: Corto y descriptivo.
  • Entorno: Win11, Java 21, Versión 1.2
  • Pasos para reproducir: El "Paso a paso" exacto para que el programador vea el error.
  • Resultado Actual: Lo que hace mal (Ej. Tira error 500).
  • Resultado Esperado: Lo que debería hacer según el cliente.
  • Evidencia: Logs, capturas de pantalla, videos.

Severidad vs. Prioridad

Severidad (Impacto Técnico)

¿Qué tanto daño le hace el error al sistema?

Alta El sistema crashea o borra datos.

Media Falla una función, pero hay alternativas.

Baja Error ortográfico en un menú oculto.

Prioridad (Impacto de Negocio)

¿Qué tan rápido necesitamos arreglarlo?

Ejemplo trampa: El logo de la empresa en la página de inicio está mal escrito.

Severidad Baja (el sistema funciona perfecto).

Prioridad ALTA (Marketing nos exige arreglarlo ¡YA!).

El Mal Reporte vs. El Buen Reporte

El Inservible

Título: No anda la inscripción.

Pasos: Intenté anotar a un chico y tiró error.

Resultado: Arréglalo.

El Profesional

Título: Falla lógica al validar edad = 18 en frm_inscripcion.

Pasos: 1. Abrir app. 2. Ingresar DNI. 3. Poner edad '18'. 4. Clic en Guardar.

Res. Actual: Mensaje "Edad inválida".

Res. Esperado: Inscripción exitosa según Ley vigente.
